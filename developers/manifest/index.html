Connector manifest

A connector is a JSON file the app reads, not a program it runs. This page is every key that file can hold, generated from the app’s own rules.

Draft. Connectors are not released yet, and this page may change before they are. The rules below are generated from lib/plugin-manifest.js at 216f6ce70, and the JSON Schema is at /schemas/plugin-manifest-v1.json.

The file

A manifest is one JSON object. Keys the app does not know are refused, not ignored, so a typo fails loudly. Labels — name, a field’s or a button’s label — are objects keyed by language, {"en": "Book pickup", "ar": "…"}; English is required and is shown wherever a translation is missing.

Top-level keys
KeyRequiredWhat it is
khaytRequiredAlways {"manifest": 1}. Tells the app which version of these rules the file is written to.
idRequiredYour connector’s permanent identifier, reverse-DNS in lower case, for example com.example.courier. It never changes between versions.
nameRequiredThe name shops see, as a label: {"en": "…", "ar": "…"}. English is required; other languages are optional.
publisherRequiredWho makes the connector, as shops will see it.
versionRequiredYour version, major.minor.patch. Shops are asked again only when a new version asks for more.
descriptionOptionalOne or two sentences on what the connector does, as a label.
homepageOptionalAn https page about the connector, including your privacy policy.
domainsOptionalEvery host the connector sends to or opens, lower case, no scheme. Each must be used by an action or event, and each is shown to the shop before it agrees.
secretsOptionalValues the shop types in once and the device keeps in its own protected storage: API keys, tokens, signing keys. Never synced, never sent to Khayt Cloud.
fieldsOptionalFields the connector adds to a record, which the shop can fill in and the connector can send or fill from a reply.
actionsOptionalButtons the connector adds beside an order or a customer.
eventsOptionalThings that happen in the shop that the connector is told about, as they happen.
scopesOptionalWhat the connector may do to the shop, beyond sending the fields it lists.
signatureOptionalAdded by Khayt when a connector passes review: an ed25519 signature over the canonical JSON of everything else. Leave it out while you develop.

Buttons (actions)

Kinds of button
ValueMeaning
postSends the listed fields to a URL on one of your domains, and can fill your own fields from the reply.
openOpens a URL in the browser. It sends nothing else, and a secret can never appear in it.

A URL must start https:// followed by one of your domains, written literally: a placeholder can appear in the path or query, never in the host, so a value from the book can never choose where data goes. A post button can authenticate with auth (a header filled from one of your secrets) and sign the request with signWith. Its response can copy values from your reply into your own fields — {"fields": {"tracking": "data.trackingNumber"}} — and only into fields on the same kind of record as the button.

Body formats
ValueMeaning
khayt-v1The default: a JSON object with the fields you listed in send.
json-templateYour own JSON shape, up to 4 levels deep, with {placeholders} naming sendable fields.

Events (events)

Each entry names an event, the URL it is sent to, and the fields it sends, with the same send, body, auth and signWith as a button. Every event carries one order. The event reference describes each payload.

Secrets (secrets)

Kinds of secret
ValueMeaning

A secret can be used in a post URL, an auth header or signWith. It can never be sent as a field, put in a body template, or appear in an open link, which a browser would keep in its history.

Review and signing

A connector counts as reviewed only when its signature verifies — never because of a flag stored anywhere. Khayt signs a manifest it has reviewed with ed25519 over the UTF-8 bytes of its canonical JSON: every key sorted, no whitespace, signature itself left out. Any change to a signed manifest, even to a URL, breaks the signature and needs a new review. A signature verifies against any of these published keys, so the key can rotate without un-reviewing what was signed before:

What the shop agrees to

Before a connector is switched on, the shop sees one row per host with the fields that go there. When a new version asks for another field, another host or another scope, the connector pauses on every device until the shop agrees again; asking for less never does. Example

A courier connector: a button that books a pickup and keeps the tracking number from the reply, a link to the tracking page, and an event when an order ships. It passes the app’s validator as written.

{
  "khayt": {
    "manifest": 1
  },
  "id": "com.example.courier",
  "name": {
    "en": "Example Courier",
    "ar": "شركة الشحن المثال"
  },
  "description": {
    "en": "Book a pickup for an order and keep its tracking number on the job."
  },
  "publisher": "Example Courier Ltd",
  "version": "1.0.0",
  "homepage": "https://courier.example.com/khayt",
  "domains": [
    "api.courier.example.com",
    "track.courier.example.com"
  ],
  "secrets": [
    {
      "name": "apiKey",
      "label": {
        "en": "API key"
      },
      "kind": "apiKey"
    },
    {
      "name": "hookKey",
      "label": {
        "en": "Webhook signing key"
      },
      "kind": "signingKey"
    }
  ],
  "fields": [
    {
      "key": "tracking",
      "label": {
        "en": "Courier tracking"
      },
      "type": "text",
      "attach": "order"
    },
    {
      "key": "service",
      "label": {
        "en": "Service"
      },
      "type": "enum",
      "attach": "order",
      "options": [
        {
          "value": "standard",
          "label": {
            "en": "Standard"
          }
        },
        {
          "value": "express",
          "label": {
            "en": "Express"
          }
        }
      ]
    }
  ],
  "actions": [
    {
      "id": "book",
      "label": {
        "en": "Book pickup",
        "ar": "احجز الاستلام"
      },
      "placement": "order",
      "kind": "post",
      "url": "https://api.courier.example.com/v1/shipments",
      "send": [
        "order.number",
        "order.title",
        "customer.name",
        "customer.phone",
        "customer.address",
        "field.service"
      ],
      "auth": {
        "header": "Authorization",
        "scheme": "Bearer",
        "secret": "apiKey"
      },
      "response": {
        "fields": {
          "tracking": "data.trackingNumber"
        }
      }
    },
    {
      "id": "track",
      "label": {
        "en": "Track parcel"
      },
      "placement": "order",
      "kind": "open",
      "url": "https://track.courier.example.com/{field.tracking}"
    }
  ],
  "events": [
    {
      "event": "order_shipped",
      "url": "https://api.courier.example.com/v1/khayt/shipped",
      "send": [
        "order.number",
        "order.trackingNumber"
      ],
      "signWith": "hookKey"
    }
  ],
  "scopes": [
    "fields.write"
  ]
}
