The file

A manifest is one JSON object. Keys the app does not know are refused, not ignored, so a typo fails loudly. Labels — name, a field’s or a button’s label — are objects keyed by language, {"en": "Book pickup", "ar": "…"}; English is required and is shown wherever a translation is missing.

Top-level keys
KeyRequiredWhat it is
khaytRequiredAlways {"manifest": 1}. Tells the app which version of these rules the file is written to.
idRequiredYour connector’s permanent identifier, reverse-DNS in lower case, for example com.example.courier. It never changes between versions.
nameRequiredThe name shops see, as a label: {"en": "…", "ar": "…"}. English is required; other languages are optional.
publisherRequiredWho makes the connector, as shops will see it.
versionRequiredYour version, major.minor.patch. Shops are asked again only when a new version asks for more.
descriptionOptionalOne or two sentences on what the connector does, as a label.
homepageOptionalAn https page about the connector, including your privacy policy.
domainsOptionalEvery host the connector sends to or opens, lower case, no scheme. Each must be used by an action or event, and each is shown to the shop before it agrees.
secretsOptionalValues the shop types in once and the device keeps in its own protected storage: API keys, tokens, signing keys. Never synced, never sent to Khayt Cloud.
settingsOptionalValues the shop fills in when it sets the connector up — a sender’s name, an account number — which the connector can send as config.<key>.
fieldsOptionalFields the connector adds to a record, which the shop can fill in and the connector can send or fill from a reply.
actionsOptionalButtons the connector adds beside an order or a customer.
eventsOptionalThings that happen in the shop that the connector is told about, as they happen.
refreshOptionalAt most one: a regular check with your service for news on open jobs your connector already handles, such as delivery status.
scopesOptionalWhat the connector may change in the shop. In this version that is only its own fields.
signatureOptionalAdded by Khayt when a connector passes review: an ed25519 signature over the canonical JSON of everything else. Leave it out while you develop.

order.amountDue, order.amountDueMinor and order.amountDueCurrency are worked out when they are sent, not stored: what the customer still owes on the job, in the job’s own currency — the bill as the shop charges it, tax included where the shop adds it, less payments, gift cards and credit notes, and never below zero. amountDueMinor is the same amount as a whole number of the currency’s minor unit (halalas, cents), the integer most payment APIs take: three decimals for currencies such as KWD, BHD and OMR, and none for JPY or KRW. amountDueCurrency is the ISO 4217 code both are in: the job’s own currency, else its customer’s, else the shop’s. Send it rather than order.currency, which is empty on a job priced in the shop’s currency. All three need the shop’s settings: if the app cannot read them, the request is not sent rather than sent with the wrong amount.

Which of them a button can reach depends on where it sits: a customer has no single order, so a button on a customer cannot send order.*.

The time

For a link that expires — a payment link, say — a URL, a body template or send can use {now.epochMs}, the time in milliseconds since 1970 (UTC), or {now.plusDays.N.epochMs}, N whole days later, N from 1 to 90. The time is not shop data, so the shop does not grant it and it is not on the consent screen. It is read when each attempt is sent: a retry carries a later time, so its body is not the same bytes as the first attempt’s. Recognise a repeat by its X-Khayt-Delivery id, which every retry keeps, never by comparing bodies. An expiry N days ahead counts from the attempt that reached you, so it always gets its full N days.

Buttons (actions)

Kinds of button
ValueMeaning
postSends the listed fields to a URL on one of your domains, and can fill your own fields from the reply.
openOpens a URL in the browser. It sends nothing else, and a secret can never appear in it.

A URL must start https:// followed by one of your domains, written literally: a placeholder can appear in the path or query, never in the host, so a value from the book can never choose where data goes. A post button can authenticate with auth (a header filled from one of your secrets) and sign the request with signWith. auth is {"header", "scheme", "secret"}, plus "encode": "basic" when your API takes HTTP Basic (table below). Its response can copy values from your reply into your own fields — {"fields": {"tracking": "data.trackingNumber"}} — and only into fields on the same kind of record as the button.

Auth encodings (auth.encode)
ValueMeaning
basicHTTP Basic: the secret, as user:password, in base64 of its UTF-8 bytes, after the scheme Basic unless you name another. A secret with no colon is taken as the user name with an empty password, so a colon is added — the form a payment provider’s secret key usually takes.
Body formats
ValueMeaning
khayt-v1The default: a JSON object with the fields you listed in send.
json-templateYour own JSON shape, up to 4 levels deep, with {placeholders} naming sendable fields or the time.

Events (events)

Each entry names an event, the URL it is sent to, and the fields it sends, with the same send, body, auth, signWith and response as a button; a reply can fill your own fields on that order. Every event carries one order. The event reference describes each payload.

Events
ValueMeaning
order_createdAn order was created.
status_changedAn order’s status changed.
order_shippedAn order was marked shipped.
order_deliveredAn order was marked delivered.
payment_receivedA payment was recorded against an order.
quote_createdA quote was created.
quote_approvedA customer approved a quote.

Refresh (refresh)

A refresh asks your service, on a schedule, about jobs your connector already handles — say, a parcel’s delivery status — and fills your own fields from the reply. It runs only on the computer that has the shop’s book open, never on a phone, and only while the connector is switched on. It needs the fields.write scope.

Refresh keys
KeyWhat it is
everyMinutes between runs, a whole number from 15 to 1440.
whenOne of your own fields on an order. Only jobs where it is filled in are asked about — for example a tracking number your book button stored.
methodGET or POST; POST if left out. A GET has no body.
urlAs for a button: https, a host in your domains, placeholders only in the path or query.
send, body, auth, signWithAs for a button. Everything a refresh sends is on the consent screen.
responseRequired: the reason a refresh exists. Which of your own order fields to fill, and from which path in your reply.

Each run asks about open jobs — not cancelled, not archived, not voided and not yet delivered — one request per job, at most 50 a run, the ones asked about least recently first. A refresh is not retried; the job comes round again on a later run. Adding a refresh, or shortening its every, pauses the connector until the shop agrees again.

Settings (settings)

Each entry is {"key", "label", "type"}, with options for an enum, required if the connector cannot work without it, and, for a text setting, a kind saying what the value is. The kind decides the privacy category — a sender’s phone is a phone number, whoever’s it is — so you never name a category. A button or event that uses a required setting the shop has not filled in is not sent, and the error names the missing setting. A value of the wrong type, or text over the limit, is sent as null.

Review and signing

A connector counts as reviewed only when its signature verifies — never because of a flag stored anywhere. Khayt signs a manifest it has reviewed with ed25519 over the UTF-8 bytes of its canonical JSON: every key sorted, no whitespace, signature itself left out. Any change to a signed manifest, even to a URL, breaks the signature and needs a new review. A signature verifies against any of these published keys, so the key can rotate without un-reviewing what was signed before:

What the shop agrees to

Before a connector is switched on, the shop sees one row per host with the fields that go there. When a new version asks for another field, another host or another scope, the connector pauses on every device until the shop agrees again; asking for less never does. For the example below, the shop sees:

Example

A courier connector: a button that books a pickup and keeps the tracking number from the reply, a link to the tracking page, and an event when an order ships. It passes the app’s validator as written.
