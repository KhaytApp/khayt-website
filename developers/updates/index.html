How updates reach shops

Shops never download a connector from you. Khayt signs each version that passes review and lists it in one signed index on khaytapp.com, which every device checks. This is what a device does with it.

The signed index

One file, https://khaytapp.com/connectors/index.json, with one row per item. It says which version is current; what that version may do is still only what Khayt signed into its manifest. The signature is ed25519 over khayt-index-v1\n followed by the canonical JSON of everything except signature, so an index signature can never pass as a manifest’s, or the other way round. The serial only ever rises.

An index row
KeyMeaning
kindWhat it is: one of connector, plugin, addon. A row of a kind this app version does not know is skipped, not an error.
idThe manifest’s id.
versionThe current version. Older versions are not listed; a device only ever moves forward.
urlWhere the signed manifest is: https, on khaytapp.com.
sha256SHA-256 of the file at url, 64 lower-case hex digits. A download that does not match is thrown away.
sizeOptional: the file’s size in bytes, checked with the hash.
requiresOptional: schema, the manifest format the version needs, and the oldest app version per platform (mac, desktop, ios). An older app is told the update needs a newer Khayt, and keeps the version it has.
revokedOptional: versions Khayt has withdrawn, each { version, reason }. The reason is shown to the shop, up to 200 characters.

What a device does with a new version

A device downloads the manifest from the row’s url, checks its SHA-256, then the manifest’s own signature, then compares what it asks for with what the shop agreed to.

Update outcomes
When the new version…What happens
asks for nothing newInstalls by itself on the Mac and on Windows and Linux, with a quiet “Updated to 1.2.0 · Revert” note. Nothing new means the same fields to the same hosts, with the same scopes and refresh: a field sent to a different host counts as new.
asks for moreWaits for the shop’s yes on a sheet that shows what is new, and the installed version keeps running until then. “Not now” asks again only for a newer version.
needs a newer KhaytThe shop is told the update needs a newer Khayt, and keeps the version it has.
is withdrawnIt is paused on every device, with the reason. This is the one case a running connector stops without the shop’s word. A withdrawn version is never kept to revert to.
is a plugin (plugin)It never updates by itself, even asking for nothing new, until there is a sandbox for it.

The iPhone shows updates and the previous version, and takes the change from the shop’s Mac.

Revert

After an update, the shop can go back to the version it had, with the permissions it had. A version a shop reverted is never installed by itself again; a later version can be.

When the index cannot be trusted

Nothing changes: no update, no pause, and every connector keeps running as it is. A device remembers the highest serial it has accepted, so an older index cannot bring back a version withdrawn since.

Why an index is refused
ReasonMeaning
unreadableThe index is not in the format this app reads, or a row is malformed.
unsignedNo signature from a published Khayt key.
old_serialIts serial is lower than one this device has already accepted: an older index served again.
expiredPast its expires date. Khayt re-signs the index every 30 days, and each is good for 45.
from_futureIssued more than a day ahead of this device’s clock.

What this means for you

Raise version for every change you send for review. If a version sends the same fields to the same hosts as the one before, shops get it without being asked. If it sends anything new, every shop is asked, and some will say not now: keep the old behaviour working on your side until they agree.
