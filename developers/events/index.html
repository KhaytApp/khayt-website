The body

Unless a trigger sets body.format to json-template, Khayt sends a plugin-payload-v1 object: your connector’s id and version, which button or event caused it, and under data exactly the fields the trigger lists in send, keyed by their names. A field with no value is null. Keys are sorted, and the body is sent as compact JSON, the same bytes from a Mac, a PC or an iPhone.

The bodies above are shown exactly as sent, on one line: the signatures are over these bytes, so you can check the recipe below against them with the key example-signing-key.

Headers

Headers
HeaderWhenValue
Content-TypeOn a POSTapplication/json
X-Khayt-EventAlwaysThe event name, the button’s id, or refresh.
X-Khayt-DeliveryAlwaysdlv_ and a lower-case UUID: one per button press or event. A retry sends the same id, so you can ignore one you have already handled. Compare ids, not bodies: a body that carries the time changes on each attempt.
Your auth.headerIf the trigger has authIts scheme, a space, and the secret the shop typed in — or just the secret when the trigger sets no scheme. With "encode": "basic", Basic and the secret in base64 (see the manifest).
X-Khayt-TimestampIf the trigger has signWithUnix time in seconds.
X-Khayt-SignatureIf the trigger has signWithHMAC-SHA256 of the body under the signing key, lowercase hex, no prefix.
X-Khayt-Signature-V2If the trigger has signWithHMAC-SHA256 of <timestamp>.<body>, lowercase hex. Check this one: it also lets you refuse a replay.

Checking a signature

Compute the HMAC over the raw bytes you received, not over JSON you parsed and wrote out again. This recipe is run against a real signature from the app every time this page is built.

JavaScript
const crypto = require('crypto');

// body: the raw request body, exactly as received (before any JSON parsing).
function verify(body, headers, signingKey) {
  const ts = headers['x-khayt-timestamp'];
  const v2 = headers['x-khayt-signature-v2'];
  if (!ts || !v2) return false;
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false; // refuse replays
  const want = crypto.createHmac('sha256', signingKey).update(ts + '.' + body).digest('hex');
  return v2.length === want.length &&
    crypto.timingSafeEqual(Buffer.from(v2), Buffer.from(want));
}

Delivery

  • Events are tried up to 5 times — at once, then after 30 seconds, 2 minutes, 10 minutes and 1 hour — until you answer with any 2xx. 410 Gone stops the retries and switches that event off for the shop.
  • Buttons are never retried: a person pressed it and sees the result. Any 2xx is success. Anything else, a timeout (15 seconds) or a redirect (never followed) shows the shop “your connector’s name answered status” or “could not be reached”, and nothing is written.
  • A refresh is never retried: the job is asked about again on a later run.
  • Requests go only over https, only to a host in your domains, and never to a private or local address.

Your reply

If a button, an event or the refresh declares response, answer with JSON of up to 64 KB. Each path it names is read from your reply and written to your connector’s own field on that record, after a check against the field’s type: a number may arrive as numeric text ("2.5"), a date as a full date-time (the date part is kept), and text is cut to 500 characters; a yes/no field takes only true or false, a choice only one of its option values, and anything else of the wrong type is dropped. This needs the fields.write scope. A reply that is not JSON, or too large, still counts as success; nothing is filled in.
